# Запуск MediaBot на Android через Termux

Бот умеет работать в двух режимах. На сервере — `distributed`: PostgreSQL,
Redis и Celery-воркеры в отдельных контейнерах. На телефоне — `standalone`:
**один процесс**, база SQLite, кэш в памяти, загрузчик работает внутри бота.
Никаких PostgreSQL, Redis и Celery ставить не нужно.

---

## 1. Что понадобится

| Требование | Комментарий |
| --- | --- |
| Termux | Только из **F-Droid** или GitHub. Версия из Google Play устарела и ломается на новых Android |
| ~1.5 ГБ свободного места | Python, ffmpeg, зависимости и место под скачиваемые файлы |
| Android 7+ | Проверено на Android 10–14 |
| Токен бота | Получить у [@BotFather](https://t.me/BotFather) |
| Ваш Telegram ID | Узнать у [@userinfobot](https://t.me/userinfobot) |

---

## 2. Установка одной командой

Откройте Termux и выполните:

```bash
pkg update -y && pkg install -y git
git clone <адрес-репозитория> mediabot-repo
cd mediabot-repo/mediabot
bash termux/install.sh
```

Скрипт сам:

1. поставит `python`, `ffmpeg`, `libmagic`, `clang` и прочее из репозитория Termux;
2. создаст виртуальное окружение `.venv`;
3. установит бота профилем `standalone` — **без** `psycopg2`, `celery`,
   `bcrypt` и `psutil`, которые в Termux требуют компилятора и часто не собираются;
4. спросит токен бота, юзернейм и ваш Telegram ID;
5. сгенерирует секреты и создаст `.env`;
6. создаст базу SQLite и применит миграции;
7. проверит окружение и покажет пароль от админ-панели.

Установка занимает 5–15 минут — дольше всего ставится `ffmpeg`.

---

## 3. Запуск

```bash
bash termux/run.sh
```

В логе появится `running in long-polling mode` — можно писать боту в Telegram.
Остановить: `Ctrl+C`.

Другие режимы:

```bash
bash termux/run.sh api      # REST API и веб-панель на http://127.0.0.1:8000/admin
bash termux/run.sh migrate  # применить миграции после обновления
bash termux/run.sh doctor   # диагностика: что установлено, что не так
```

> Веб-панель слушает только `127.0.0.1`, то есть доступна лишь с самого
> телефона (откройте адрес в браузере). Наружу она не торчит — это осознанно.

---

## 4. Чтобы Android не убивал бота

Это главная причина, по которой «бот перестал отвечать через 10 минут».

1. **Wake lock.** Опустите шторку уведомлений → в уведомлении Termux нажмите
   **«Acquire wakelock»**. Скрипт `run.sh` вызывает `termux-wake-lock`
   автоматически, если установлен пакет `termux-api`, но системный wakelock
   надёжнее:
   ```bash
   pkg install termux-api
   ```
2. **Отключите оптимизацию батареи** для Termux:
   Настройки → Приложения → Termux → Батарея → **Без ограничений**.
3. На MIUI / EMUI / ColorOS дополнительно включите **автозапуск** для Termux
   и закрепите приложение в списке недавних (замок в карточке приложения).

## 5. Автозапуск при перезагрузке телефона

Установите **Termux:Boot** (F-Droid), запустите его один раз, затем:

```bash
mkdir -p ~/.termux/boot
cp termux/boot-mediabot.sh ~/.termux/boot/mediabot.sh
chmod +x ~/.termux/boot/mediabot.sh
```

После перезагрузки бот стартует сам. Лог: `~/mediabot/logs/`.

Чтобы бот пережил закрытие сессии Termux, запускайте его через `tmux`:

```bash
pkg install tmux
tmux new -s bot 'bash termux/run.sh'
# отсоединиться: Ctrl+B, затем D
# вернуться:    tmux attach -t bot
```

## 6. Что работает, а что нет

| Возможность | Termux (standalone) | Сервер (distributed) |
| --- | --- | --- |
| Скачивание видео и музыки | ✅ | ✅ |
| Выбор качества и формата, превью | ✅ | ✅ |
| Очередь, прогресс, отмена | ✅ (в процессе бота) | ✅ (Celery) |
| Тарифы, лимиты, промокоды, рефералы, монеты | ✅ | ✅ |
| История, избранное, достижения, 5 языков | ✅ | ✅ |
| Админ-панель в боте | ✅ | ✅ |
| Веб-панель и REST API | ✅ (только localhost) | ✅ |
| Платежи Telegram Stars | ✅ | ✅ |
| Метрики Prometheus / Grafana | ⚠️ метрики есть, дашборды не разворачиваются | ✅ |
| Точные метрики CPU/RAM (`psutil`) | ⚠️ упрощённые | ✅ |
| Хеширование паролей панели | PBKDF2 (600k итераций) | bcrypt |
| Горизонтальное масштабирование | ❌ один процесс | ✅ |

Ограничения телефона, о которых стоит знать заранее:

* **Файлы до 50 МиБ.** Это лимит облачного Bot API, а не бота. Больше — только
  со своим Bot API сервером, а его на телефоне поднимать не стоит.
* **Параллельных загрузок 2** (`DOWNLOADER__MAX_CONCURRENT_JOBS`). Больше —
  телефон греется, Android начинает убивать процессы.
* **4K и длинные видео** упираются в память: склейка видео и звука в ffmpeg на
  телефоне заметно медленнее и может не завершиться. Для личного использования
  разумный потолок — 1080p.
* **Мобильный трафик.** Каждое видео скачивается на телефон и заливается в
  Telegram, то есть расходуется двойной объём трафика.

## 7. Настройка

Все параметры — в файле `.env` рядом с проектом. Часто меняемое:

```bash
# Сколько загрузок одновременно (на телефоне больше 2 обычно вредно)
DOWNLOADER__MAX_CONCURRENT_JOBS=2

# Через сколько минут удалять скачанные файлы с телефона
APP__ARTIFACT_TTL_MINUTES=30

# Жёсткий потолок размера файла (байты)
DOWNLOADER__ABSOLUTE_MAX_FILESIZE_BYTES=2147483648

# Порог антифлуда: сколько сообщений за 5 секунд считается флудом
SECURITY__FLOOD_THRESHOLD=8
```

После изменения `.env` перезапустите бота.

Лимиты тарифов (сколько скачиваний в сутки, какое качество) задаются не в
`.env`, а в коде — `src/mediabot/domain/policies.py`. Для личного бота удобно
выдать себе тариф Lifetime: отправьте боту `/admin` → «Пользователи» → найдите
себя → «+30d 💎», либо через веб-панель.

## 8. Обновление

```bash
cd mediabot-repo
git pull
cd mediabot
source .venv/bin/activate
pip install -e ".[standalone]" --upgrade
bash termux/run.sh migrate
bash termux/run.sh
```

Отдельно стоит регулярно обновлять `yt-dlp` — площадки часто ломают выгрузку:

```bash
source .venv/bin/activate && pip install --upgrade yt-dlp
```

## 9. Если что-то не работает

Первым делом:

```bash
bash termux/run.sh doctor
```

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `ffmpeg не найден` | не установлен пакет | `pkg install ffmpeg` |
| `TELEGRAM__BOT_TOKEN пустой` | не заполнен `.env` | откройте `.env` и впишите токен |
| `no such table: users` | не применены миграции | `bash termux/run.sh migrate` |
| `database is locked` | два запущенных экземпляра бота | оставьте один: `pkill -f "mediabot bot"` |
| Бот отвечает, но не скачивает | нет ffmpeg или нет места | `doctor`, затем освободите память |
| Бот замолкает при выключенном экране | Android усыпил процесс | wake lock + отключить оптимизацию батареи (раздел 4) |
| `Unable to extract` / `HTTP Error 403` | площадка изменила API | `pip install --upgrade yt-dlp` |
| Ошибка сборки `bcrypt` / `psycopg2` | ставили не тот профиль | используйте `pip install -e ".[standalone]"` |
| `Insecure production configuration` | в `.env` стоит `APP__ENV=production` | поставьте `APP__ENV=local` |

Логи по категориям лежат в `~/mediabot/logs/`:
`error.log`, `download.log`, `security.log`, `payments.log`, `admin.log`.

```bash
tail -f ~/mediabot/logs/error.log
```

## 10. Переезд с телефона на сервер

База SQLite и настройки полностью совместимы по схеме с PostgreSQL —
миграции одни и те же. Порядок переезда:

1. на сервере разверните стек по [DEPLOY.md](DEPLOY.md);
2. перенесите данные (например, через `pgloader` или экспорт нужных таблиц);
3. в `.env` сервера уберите `APP__RUNTIME_MODE=standalone`, `DB__BACKEND=sqlite`
   и `REDIS__ENABLED=false`.

Пароли админ-панели, созданные на телефоне (PBKDF2), продолжат работать на
сервере — схема хеша хранится вместе с самим хешем.
